# ADR-010: Dutch and English with compile-time i18n

**Status:** accepted · 2026-09

## Context

The app should speak Dutch as well as English. Two established approaches fit Angular 22:

- **Transloco** (runtime): one build, translation files fetched at start-up, the language switched
  in place.
- **`@angular/localize`** (Angular's own, compile-time): the text is marked in templates (`i18n`)
  and code (`$localize`), extracted to a source file, and every language is compiled into its
  own build with its text inlined.

The first-load budget was already within a few hundred bytes of its 500 kB warning, and the app
renders on a slow API behind skeletons: a translation request before the first paint, or English
flashing before Dutch arrives, would both be visible.

## Decision

Compile-time i18n with `@angular/localize`.

- Text is marked where it lives: `i18n` / `i18n-<attribute>` in templates, `$localize` with named
  placeholders in TypeScript. Counts with a singular and a plural form are ICU plurals, so Dutch
  can inflect them ("1 tuin" / "3 tuinen").
- `npm run i18n:extract` writes the English source, `src/locale/messages.json`;
  `src/locale/messages.nl.json` holds the Dutch. The production build fails on any message
  without a translation (`i18nMissingTranslation: error`).
- The production build is one build per language, under `/en/` and `/nl/`, each with its own
  `<html lang>`, number and date formats (`15,8 m²` in Dutch).
- The switch in the top bar (EN | NL) loads the other build on the same route and remembers the
  choice in a `lang` cookie. The host sends `/` and any path outside a language to the cookie's
  language, else the browser's, else English (`tools/serve-dist.mjs` implements this).
- The development server serves one language at `/` (English; `npm run dev:web:nl` for Dutch), so
  the switch is hidden there. The `$localize` polyfill is loaded only by the development build and
  the unit tests: production text is inlined and needs no runtime.
- Data stays as the user entered it: garden and plant names, and messages the API writes, are not
  translated.

## Consequences

- No translation runtime, no request before the first paint, no flash of the wrong language.
- Template i18n adds Angular's i18n runtime to the first load, about 9 kB. The initial-bundle
  warning moves from 500 kB to 520 kB; the 600 kB error stays the hard limit.
- Switching language is a page load rather than an in-place swap; a new language is a new
  build and a new folder on the host.
- The host must route `/en/` and `/nl/` with their own SPA fallback — one more rule next to the
  `/api` proxy (PRODUCTION-READINESS.md).
